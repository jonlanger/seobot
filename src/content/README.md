# src/content

Render-ready content, typed against the contracts in `docs/content-models.md` and the
GEO research in `docs/geo-research.md`.

## Files

| File | Contents |
|---|---|
| `types.ts` | Shared primitives (`PageSeo`, `Hero`, `Cta`, `FaqItem`, …) + template interfaces (Home, Pricing tier) |
| `site.ts` | Sitewide constants (`site` object: name, legalName, url, support email, `sameAs`) |
| `schema.ts` | JSON-LD builders (`organizationSchema`, `websiteSchema`, `softwareApplicationSchema`, `faqPageSchema`, `breadcrumbListSchema`, `definedTermSchema`, `techArticleSchema`) — single home for all schema |
| `pricing.ts` | Pricing tiers + annual discount — for the future `/pricing` page (removed from the home page 2026-10-16) |
| `home.ts` | `/` — hero, definition band, coverage strip, evidence (sourced stats + comparison table), features, how-it-works, testimonial, FAQ, final CTA |
| `ai-crawlers.ts` | `/ai-crawlers` — crawler records, robots.txt template, verification checklist, FAQ |
| `glossary.ts` | `/glossary/{slug}` terms — definition-first, sourced stats, related-term links |
| `study-facts.ts` | Headline figures for copy (counts, shares, quartiles), generated into `study-facts.json` by `scripts/build-study-facts.mjs`. Marketing and SEO copy import this ~2 KB file, never the study JSON, and never type a number |
| `top-sites.ts` | The dashboard's study dataset — types + decode for `data/top-sites-study-1k.json` (every crawled site, ranks 1 to N) (generated by `scripts/build-top-sites-data.mjs` from `tools/crawl/out/`; never hand-edit the JSON), plus ranking/method/caveat copy |
| `brand.ts` | Brand voice, tone matrix, taglines, copy patterns, logo/asset specs — rendered by the Brand view |

## Conventions

1. **Definition-first**: `definition` fields must work out of context — they are the passages AI engines quote.
2. **Sourced facts only**: stats use `number + unit + source + year`. No unsourced superlatives.
3. **Dates are real**: `publishedAt`/`updatedAt` are ISO dates; update `updatedAt` only on meaningful edits.
4. **JSON-LD mirrors visible copy** exactly (FAQ answers, breadcrumbs, term definitions). Builders live in `schema.ts`; never hand-write schema objects in content modules.
5. **Related links must resolve**: `relatedTerms` reference slugs exported from the same module.
6. **Placeholders are marked**: `site.ts` uses an example URL; CTA hrefs resolve through `src/lib/demo-links.ts` inside the demo — both carry `TODO(launch)` notes.
7. **Brand copy is illustrative**: `brand.ts` examples are voice samples, not published claims — copy them into pages, then source any stats before shipping.
8. **Study data is generated, not written**: `top-sites.ts` consumes `data/top-sites-study-1k.json`, derived from the crawl by `npm run data:top-sites`. Re-run the crawl + derivation instead of editing numbers.

## Adding content

- New glossary term: add a `buildGlossaryTerm({...})` entry — keep 20 excellent terms over 200 stubs,
  and only if it adds value beyond the current first SERP result.
- New template: define its interface in `types.ts` once more than one module needs it, and flag the
  addition in `docs/content-models.md`.
